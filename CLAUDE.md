# TransportApp — указания для Claude

Попутчики по маршрутам Еревана: приложение пассажира и приложение водителя (Flutter), веб-панель сотрудников (позже),
сервер на Supabase. Подробно — [README.md](README.md), ТЗ — [docs/TZ.md](docs/TZ.md), схема «виртуальной модели» —
[docs/virtual-model.html](docs/virtual-model.html).

## Как работать с владельцем проекта

- Отвечать **по-русски, просто, без технического жаргона**. Владелец — не программист: объяснять, что изменилось
  для водителя или пассажира, а не как устроен код.
- Он часто управляет сессией с телефона (Remote Control) и не видит окно с кнопками в конце хода: вопрос, который
  требует его решения, повторять обычным текстом в конце сообщения.
- После изменений в приложении — проверить на эмуляторе, собрать установочный файл и **отправить его файлом**
  (SendUserFile): он ставит его на свой телефон Samsung (Android, arm64).
- Работает с **двух компьютеров** (рабочий и домашний) через GitHub, ветка `feature/prototype`. В начале работы —
  `git pull`, в конце — коммит и `git push`, чтобы на другом компьютере было всё. Пути к инструментам на компьютерах
  разные: не прописывать их в файлы проекта.

## Нельзя

- Ключ Яндекс MapKit лежит только в `mapkit.json` (git его не сохраняет). Не коммитить, не печатать, не отправлять.
  На новом компьютере владелец копирует файл сам.
- Не коммитить и не печатать секреты Supabase (service_role, пароль базы).
- Номера телефонов водителей и пассажиров друг другу не показываются — ни в приложениях, ни в данных модели.
- Учётные записи (Supabase, Яндекс и др.) создаёт сам владелец.
- В модели — никаких настоящих документов и номеров карт: только тестовые (например 4111 1111 1111 1111).

## Сервер

- Код сервера — файлы в `supabase/migrations` (по порядку имён). `supabase/local/shim.sql` — только для локальной копии,
  в облако не применяется.
- Приложения только **читают** таблицы (правила видимости + права на столбцы). Любое изменение — через серверную
  функцию `security definer` с `set search_path = public, pg_temp`; функция сама проверяет, кто просит и можно ли;
  отказ — исключение с кодом ЗАГЛАВНЫМИ буквами (приложение переводит код в понятный текст).
- Блокировки строк — `for no key update`, порядок: водитель → маршрут → рейс → бронь.
- Новое правило = **новый файл миграции** (старые не менять) + проверки в `tools/server_tests`.
- Проверки: локальная копия сервера (PostgreSQL на порту 54329), запуск `dart test -j 2` в `tools/server_tests`
  (подробно — [tools/server_tests/README.md](tools/server_tests/README.md)). Перед коммитом серверных изменений
  все проверки должны проходить.
- Облако: Supabase, проект `transportapp-test` (ref `xfocvxrkwzzcscjwtcnq`, Франкфурт, бесплатный). Новая миграция
  выкладывается через коннектор Supabase (`apply_migration`, текст файла без изменений), затем сверка
  [tools/cloud_fingerprint.sql](tools/cloud_fingerprint.sql) на облаке и на чистой локальной базе — все строки должны
  совпасть. Замечания проверки безопасности, которые так задуманы: представления `driver_public` и `my_ratings`
  (security definer) и серверные функции, доступные вошедшим (каждая проверяет права сама).

## Приложения

- Flutter 3.50, JDK 21 (нужна модулю Яндекс MapKit), Android SDK 36. Ключ карты передаётся при сборке:
  `--dart-define-from-file=../../mapkit.json`.
- Ядро и его проверки: `packages/core` (`dart test`); общий интерфейс и карта: `packages/ui`.
- Установочный файл для телефона (в папке приложения):
  `flutter build apk --release --split-per-abi --target-platform android-arm64 --dart-define-from-file=../../mapkit.json`,
  затем скопировать `build/app/outputs/flutter-apk/app-arm64-v8a-release.apk` в `build/TransportApp-driver.apk`
  (или `-passenger.apk`) в корне проекта и отправить файлом. Размер ~25 МБ.
- Эмулятор x86_64: ставить отладочную сборку `flutter build apk --debug --dart-define-from-file=../../mapkit.json`.
  Снимки экрана — через bash (`adb exec-out screencap -p > файл`): в PowerShell перенаправление портит PNG.

## Где остановились (20.11.2026)

Сделано:
- Приложение водителя по согласованной роли: оформление (анкета, документы, карта для выплат), главный экран —
  поиск маршрута «Откуда / Куда», выбор маршрута касанием линии на карте, «Мои рейсы», заработок, профиль.
- Места машины: переднее и два сзади (среднего нет); в анкете — какие продаются, в рейсе — все или часть, у каждого
  своя цена.
- Место посадки и высадки — любая точка (дом, двор, остановка) внутри круга 1,5 км у начала и у конца маршрута.
- Сервер с этими правилами — в облаке, совпадает с локальной копией; 257 серверных проверок проходят.
- Приложения пока работают на демо-данных в телефоне, к серверу ещё не подключены.
