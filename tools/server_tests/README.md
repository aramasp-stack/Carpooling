# Проверки сервера TransportApp

Тесты работают с **локальной копией сервера**: обычный PostgreSQL на этом компьютере, к которому применяются те же файлы
из `supabase/migrations`, что и к облачному Supabase. Телефоны и интернет не нужны.

Виртуальные пользователи (пассажиры, водители, сотрудники) обращаются к базе так же, как приложения: под ролью
`authenticated` и со своим «токеном входа». Поэтому проверяются те же правила доступа и те же серверные функции.

## Запуск

1. Запустить локальную базу (порт 54329, данные в `C:\Users\AW_001\dev\pgdata`):

   ```powershell
   & C:\Users\AW_001\dev\pgsql\bin\pg_ctl.exe -D C:\Users\AW_001\dev\pgdata -o "-p 54329 -c listen_addresses=localhost -c max_connections=200 -c fsync=off" -l C:\Users\AW_001\dev\pgdata\server.log start
   ```

2. Запустить все проверки:

   ```powershell
   cd tools/server_tests; dart test
   ```

Большая симуляция с другим объёмом и другим сценарием:

```powershell
$env:SIM_STEPS = '10000'; $env:SIM_SEED = '7'; dart test test/simulation_test.dart
```

Одинаковый `SIM_SEED` повторяет тот же сценарий — так воспроизводится найденная ошибка.

## Что проверяется

| Файл | Что делает |
| --- | --- |
| `test/rules_test.dart` | Полный путь поездки и все отказы: рейс, бронь, отмена за 61 и 59 минут, отказ банка, повтор операции, начисление, выплата |
| `test/concurrency_test.dart` | Одновременные действия: 60 человек покупают одно место, дубли одной операции, отмены вперемешку с покупками |
| `test/access_test.dart` | Доступы: кто что видит, попытки изменить данные в обход серверных функций, вход без авторизации |
| `test/simulation_test.dart` | Случайная симуляция: 40 пассажиров и 10 водителей действуют одновременно, часы сервера идут вперёд |
| `lib/invariants.dart` | 18 проверок целостности, которые должны выполняться всегда: место не продано дважды, деньги сходятся до драма |

Каждый файл создаёт свою базу (`tt_rules`, `tt_concurrency`, `tt_access`, `tt_sim_<зерно>`), поэтому файлы и несколько
агентов могут работать одновременно и не мешать друг другу. Новому набору проверок — своё имя базы.

## Управляемые «внешние сервисы»

- **Банк.** Симулятор: карта с номером на `…0002` — отказ, на `…0119` — банк недоступен, остальные проходят.
- **Часы.** `World.advance(Duration)` переводит время сервера вперёд: так проверяются отмена за час до рейса и начисление через 24 часа.
- **SMS.** Вход считается выполненным: `World.newUser` создаёт пользователя, как после кода из SMS.

Локальная база принимает подключения без пароля, но только с этого компьютера. В ней нет настоящих данных.
